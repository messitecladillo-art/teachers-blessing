# 扫描教材：一键导入、覆盖与恢复

更新口径：2026-11-17。主入口已是**一键全书解析**，无需每次手选下一批5页。范围OCR与课程提案保留作高级修复工具；本文末尾的6项测试是底层恢复机制的历史回归，不代表当前完整导入功能只覆盖这些用例。

## 自动主线按真实章节推进

上传后启动导入，持久父任务自动协调文字提取、必要OCR、真目录识别、按章知识点萃取和讲义准备。默认全书与全部讲义，也可选择已有真实章节或只备首章/暂不备课。已完成章节可先学。

1. 先提取文字层和书签，检查可见目录与实际正文章首。扫描件必要时自动OCR前置目录页；不能可靠确定所有章首时继续扫描定位，不由前缀一个标题推断整书只有一章。
2. 校准目录印刷页与PDF物理页。映射不可靠时进入“目录待核对”，用户保存真实目录后可显式继续。不把页块fallback当真实章。
3. OCR每批最多5页、结构片段最多20页并受字符预算约束，均是内部安全边界。60页章分片后合回同章，跨章20页不会拼成一章。
4. 来源校验后将知识点合回原章，再逐点准备讲义；AI结构待核对，单章失败时保留已完成章节。

在物理正文章标题识别路径中，识别出的习题答案、参考文献、索引或附录可作为正文末章截止信号，避免混入末章教学内容。前置目录、封面和章后材料仍计全书文字/OCR核算，不为凑覆盖创建假章；复杂排版或OCR误识仍须核对。

## 持久进度与恢复

进度以真实章、知识点与讲义为主，页数仅作覆盖指标；未选章deferred不计入本次就绪分母。取消传播当前子任务，成功落盘结果保留；重启中断后显式继续，完成分片复用，不后台无限重试。

默认累计100次模型请求，可显式提高至200，仍受每日预算约束。逐知识点联网研究计一次请求，托管搜索费用另计。达到预算、缺包或目录待核对时停下并保留进度；处理后继续。文件替换或处理中人工改目录阻止迟到覆盖；仅待核对阶段可绑定同一文件的人工目录继续。

模型请求发出但回执丢失时可能已经计费，不能当作从未调用；本机继续不保证供应商幂等。空白/未识别页记已尝试与警告，不反复OCR至无限循环，也不造文字。接口见[一键导入](book-import.md)。

## partial与可学习章节分别表示

有文字只说明取得可整理文本，不证明识别正确或完整。无文字可能是真空白、失败或资源限制；全书仍有无文字页时保留partial。partial中有文字的章节可整理并附缺字警告；来源范围还须按实际页覆盖核对，旧知识点字符串非空不能掩盖原页无文字。

本轮隔离处理一份416页扫描输入，414页取得文字、5个正文真章；2页仍无文字。全书范围纳入调度与核算，不等于416页全可读。该轮外部provider调用为0，知识点与讲义采用Mock验证自动课程链，不证明真实模型整本学科质量或实际教学效果。

## 高级范围修复与历史底层合同

普通文字提取不会为了找文字而解码 PDF 图像。若 PDF 全部页面没有文字层，服务保存实际页数、空文页和恢复状态，任务仍是 `failed`、`error.code='NO_TEXT'`，不会伪造成功课程：

```json
{
  "fileId": "owned-file-id",
  "textbookId": "owned-textbook-id",
  "pageCount": 7,
  "needsOcr": true,
  "partial": true,
  "pendingPages": [1, 2, 3, 4, 5, 6, 7],
  "blockedPages": []
}
```

这些字段出现在 `job.result`、所属文件列表，以及教材 `GET /textbooks/:id/outline`。文件和教材为 `needs-ocr`；未生成章节或知识点，文本内容接口继续拒绝未就绪读取。已有文字但仍有空文页时为 `partial`；所有页均有文字才为 `ready`。空白页也可能进入待处理集合，不能仅凭这一状态断言页面一定有可识别文字。

继续识别仍使用已有解析接口，例如：

```json
{"ocr":true,"ocrPages":5,"startPage":1,"endPage":5,"ocrLanguage":"eng"}
```

高级修复每次最多5页，可显式指定下一范围；主流程由导入协调器自动连续调度，无需重复操作。未选页保持待处理，已保存的同文件OCR文字保留；同文件活动解析拒绝并发。局部任务无新文字时失败并释放预留，其他可读页保留，不改写既有目录修订。取消、删除、属主和输入版本检查继续有效。

## 高清图像与资源边界

- 直接上传 PNG/JPEG/WebP：仍先检查文件头，边长最多4096、总像素最多12,000,000；本轮没有放宽。
- PDF 内嵌单张图：独立上限16,000,000像素，能容纳常见约2952×4124的高清扫描页。超过上限的图不会被无界解码。
- PDF OCR 画布：按页面纵横比缩小，最多12,000,000像素、每边最多4096；不通过增加画布预算适配巨大物理页面。每个已识别页面保存 `ocrRender:{width,height,scale}`，供复核实际渲染尺寸。
- 单批解析仍在固定子进程运行：256MiB V8堆、180秒时限、最多5页OCR及文本/输出预算；必要时协调器自动减小批量。全书父任务无整本5分钟截止，子任务仍受各自限制，取消会终止当前子进程。这不是操作系统沙箱或原生RSS硬限。
- 只使用本机 `chi_sim`/`eng` 语言包；缺包明确返回 `OCR_LANGUAGE_MISSING`，不联网下载。

被图像预算阻断的已尝试页面进入：

```json
{"page":2,"code":"PDF_IMAGE_PIXELS","maxPixels":16000000,"message":"PDF内嵌图像超过1600万像素，未解码或OCR；请将该页扫描图缩小至1600万像素以内后重新导入"}
```

其页码仍在 `pendingPages`。其他范围识别不会丢失这条记录；已有该页 OCR 文字时优先保留文字，不再次解码大图，不把旧文字擦成空白。修复扫描图需重新导入文件，不能保证降低PDF文件字节数就降低了图像像素。

## pdfjs 固定版本适配

当前固定 `pdfjs-dist@5.4.149` 在超过 `maxImageSize` 时默认记录警告并去掉图像。实测 `stopAtErrors:true` 仍可能在异步流错误前先完成空的 operator list/画布，因此不能只依赖该开关。

服务对正在处理的一页调用 `getOperatorList()`，短作用域观察这一版本的精确日志 `Warning: Image exceeded maximum allowed size and was removed.`；命中后记录受限页并跳过渲染/OCR。其他日志原样转发，`finally` 恢复原 `console.log`。生产固定子进程一次只处理一份文档、顺序处理页面；此适配不应直接拿到多文档并发的进程中使用。升级 pdfjs 或改变 worker 架构时必须重跑高清页和超限页测试，不可假设日志合同恒定。

## 可复现验证

`tests/study-scan-recovery.test.mjs`保留历史6项底层回归：无文字7页的页数/恢复状态、高清扫描实际OCR、超限图在worker前阻断、巨大页面缩放、5+2保留前批、受限后释放预算并保留文字。当前自动导入另由`tests/study-import.test.mjs`和独立合同测试验证跨批、真章、印刷页校准、取消/继续、预算与来源冲突；Mock课程与真实OCR/模型/浏览器分别验收。

涉及实际OCR的用例仅复制明确的本机英文语言包到隔离临时目录。未安装包时这些用例会显式跳过，不用网络补齐，也不把跳过视为OCR验证通过。OCR内容仍需用户对照原件核对；合成英文页通过不证明所有中文字体、低清/倾斜扫描或整本教材均可正确识别。

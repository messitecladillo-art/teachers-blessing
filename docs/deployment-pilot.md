# 小规模教师试点上线方案

状态：2026-11-16源码审查与拟议方案，**未部署、未做公网容量验收**。先少量邀请，按实测扩容；短信/支付关闭，不先购GPU或拆微服务。

## 推荐第一版

`浏览器 → HTTPS反向代理 → 单实例Node → 独立持久盘`，Node调用远程LLM；PDF解析/CPU OCR在受限子进程执行。只公开HTTPS，Node继续监听回环地址。上传原件、study.json、OCR语言包放持久盘，代码发布目录与数据分离；密钥只在服务端。部署托管器负责启动/重启与日志，不运行多个共享JSON的Node实例。

先做邀请/访问门；当前注册非邀请制，发链接不等于关闭公开注册。

备份也是硬门：JSON/原件/来源版本须一致快照、核hash，在**新空目录**恢复并验证登录、文件、历史及属主。备份成功不等于恢复通过。日志不记密钥/正文/完整提示，明确保留与恢复负责人。

## 大文件、CPU OCR与费用的实际边界

当前已自制验证3000页和超过31MiB PDF；未验证完整300MiB实体，更不承诺3000页稠密扫描件都可处理。现有worker保留256MiB堆、180秒、16MiB结果、400万字和单任务OCR≤5页的预算。上传容量提高不会消除这些处理上限，失败/partial须给出分范围继续或拆分提示。

现有每用户2个/全局4个任务不代替资源调度。建议OCR独立槽位先设1，解析/LLM分开计并发，实测调整。前台查询后台状态；JSON读15秒与上传10分钟分别保留。

成本验收用获授权自编样本，记模型/版本、token、耗时、调用ID与状态；按核对的当期价格结算，预算不足调用前拒绝，取消保留已消费账目。本文不报价。

## 可执行验收顺序

1. **隔离预发布**：独立域名、账号、持久目录与模型额度；用合成资料走上传→解析/OCR→讲解→练习→教学包→学生导出。确认HTTPS、来源页覆盖、隐藏答案和跨账号拒绝。
2. **运行演练**：生成中重启/取消、模型超时、磁盘接近阈值、慢上传/断传、超限与并发登录；核无重复扣费假账、无半成品ready、旧结果不复活。
3. **恢复演练**：停写快照→新目录恢复→核hash/属主→回滚发布；实测数据损失和恢复时间。
4. **有界压测**：递增并发，测读课/上传/解析/OCR/LLM；记p95、错误率、CPU/RAM、磁盘、排队与JSON大小。达到预设阈值即停，未测不写容量。
5. **邀请试点**：指定运维/费用/内容审核负责人，记录反馈和故障；阻断关闭再开放。

## 扩容触发后再做

JSON容量/写入耗时或多实例成为瓶颈时，先迁移事务数据库、共享权限及任务一致性，再扩容；验证旧ID、来源修订、答案门、幂等与回滚。BullMQ/Redis须按[官方生产指南](https://docs.bullmq.io/guide/going-to-production)配置持久性与退出。

带宽/磁盘不足再评估[S3预签名上传](https://docs.aws.amazon.com/AmazonS3/latest/userguide/PresignedUrlUploadObject.html)，保留服务端授权、完成确认、大小/类型/hash与属主核验。GPU OCR等CPU实测瓶颈后评估。**均未采用或部署。**

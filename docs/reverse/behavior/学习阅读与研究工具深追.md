# R02：学习产品深追与当前客户端差距

本轮按18个行为问题追“完整声明→调用/状态→用户价值→副本差异”，不以接口数量代表功能理解。内部逐声明hash/AST映射不复制入公开库；公开定位用文首bundle hash、函数与UTF-8区间。

**证据层级：18项有公开交付代码支持，0项由本worker做当前运行时验收。** 运行时截图、真实视觉、动画平顺度和服务成功效果仍须root复核。没有读取root-only runtime、真实用户文件、环境配置或账户状态，没有调用模型。本报告不是服务端源码恢复，也不是原TSX模块恢复。

## 1. 原站卖点是连续阅读，而不是功能按钮集合

`gMe` [1188753,1192947) 的章侧栏有两种持久模式：知识点学习与个性化总结。章节可折叠/全部折叠，知识点中英显示与宽度控制独立；模式切换记住该教材的最近知识点或最近总结章节。`H5` [1211696,1212901) 用占满应用高度的壳层与局部滚动区组织页面。侧栏收合有300ms easeInOut，内部切换250ms，正文路由淡入150ms；这些只是代码中声明的动效，不证明设备上实际流畅。

`Yit` [2585496,2587777) 按URL的 `kp/prep/view=atlas` 选择知识点阅读、章节准备或图鉴；`kit` [2565540,2570862) 把讲解/练习作为同一个知识点的页内视图。图鉴仍是章卡、难度/依赖信息及真实数据驱动的阅读入口；本worker没有发现可据以宣称自由拖拽节点连线画布的证据。

当前 `study.js:135–148` 是平面章标题+全部KP，并将结构图、总结、教学包放成独立大dialog。当前API和成果不是空的，但视觉组织把“正在学哪一点、这一章积累了什么、下一步去哪里”压成了侧栏上的一排工具按钮。对齐原站应先重建有层级的章节/知识点阅读面，再做颜色和圆角。

## 2. 知识点课程有清楚的准备门和学习门

直接调用链：`Yit → Git → kit → eJ/dOe/fOe/hOe → G1`。`G1` [881139,881922) 中lesson按原文文本读取，202/204明确转为null；plan通过章节接口读取。当前调用端实际消费的plan字段可确认是 `teaching_sequence:[{kp_id,order}]`，不能凭接口名字补造完整context/plan响应schema或后端教学策略。

`kit`区分：请求仍在等待；章plan未就绪、需准备；章plan已有但无讲义、显示“准备就绪/开始学习”；已有讲义、可进入练习。`Krt` [2540862,2544304) 给“开始学习”主操作与风格菜单；不是从头到尾常驻一串同权重按钮。风格说明来自 `Fg` [2538998,2540577)：默认中文、中文保留专业英文、全英文，风格保存和重新生成是不同动作。

当前本地真实解析、讲解版本、风格、失败恢复已存在，不能写成“未实现讲解”；缺的是清晰的章准备/开始/阅读状态。无讲义时仍可打开自测的当前行为也与目标的讲义先行门不同，这是需明确选择的产品差异。

## 3. 讲解和追问处在同一篇阅读流

`ua` [888488,894308) 的start携 `{kp_id,action:'start'|'ask',user_message?}` POST到章节teach流；`CAe`处理 `queued → queued_started → text_delta → done/error`，同时更新processSteps/searchSources。审核重生成有独立占位状态，下一次delta替换占位，而非把错误/旧内容拼进新文。状态entry绑定KP及controller，不能把流串到另一个知识点。

`pit` [2558179,2560727) 的中列是最大800px的一篇阅读区域：讲义→来源/过程→已有追问→本轮追问流→前后知识点导航。ask保留原讲义，只在后面的对话段流入新回答；底部输入固定在这一个阅读面。讲义metadata中的历史process_steps/search_sources即使流结束后仍可查看。

`bit` [2564926,2565340) 在 `sort=recommended` 且本章存在teaching_sequence时按给定order排序，否则沿教材顺序；底部前后导航可跨章。代码证明客户端使用这些数据，不证明服务端排序必然正确或有何教学效果。

当前 `study.js:147–151,184–190` 将讲义置中、KP追问放在常驻右窄栏，且job完成后才显示整段结果。轮询可作为诚实的本机任务适配保留，但用户看不到真实增量/过程；不能只放假的逐字动画或“思考中”动效冒充目标的过程事件。右侧助教若作为本项目差异保留，应可收起，正文保持连续、输入/焦点/滚动不随刷新重建丢失。

## 4. 顺滑依赖状态与滚动策略，不是只给scroll-behavior

`XJe` [2423852,2425066) 保存教材+KP滚动位置，最多200项的持久store在ua同声明。等内容可读且高度足够后用rAF恢复，超时落到当前底部；存在 `hl` 深链或正在流式时不抢回旧位置。wheel/touchstart/keydown可以中止恢复。`Yrt` [2544304,2545384) 是显式到末尾/跟随逻辑，wheel会解除跟随。

当前course重建整个shell，`showMessages`末尾直接 `scrollTop=scrollHeight`。这会让阅读位置、选区和键盘输入感到突兀。下一实现应保持阅读容器身份，只局部更新任务/消息段；自动滚动必须尊重用户刚才的wheel/touch，切KP和跳笔记也应具有明确优先级。150–300ms的opacity/transform动效可以辅助，但不能掩盖重建DOM造成的跳动。

## 5. 练习是逐题学习循环，不是整页答案表单

`Rtt` [2465827,2469834) 的配置明确“基于这份讲义与你的划重点出题”，独立题目语言zh/en，总题数1–5，选择/简答配比始终和总数一致。quote的 `mc/exp` 与生成的 `language/requested_mc/requested_exp`是不同合同。充值和费用界面不属于当前启用范围，不能照抄成虚假本机交易。

`jnt` [2507595,2509265) 组织配置、活动题集、历史题集三种状态；刷新会重挂活动set。`ks`（UI引用名，底层store为mp声明）以setId+qid维护entry：逐题草稿、busy、attempt、answerKey、flag；`oAe`把选择题转 `{choice}`，简答转 `{text}`。提交的attempt_id按答案签名重试复用，pending/grading继续轮询，graded/failed收束。`zV`不仅画分数，还展示verdict、feedback_md、逐条covered/未覆盖与修改后重交。

当前本地已有真正题集历史、本人attempt、隐藏答案、评分失败/取消和新作答ID。主要差别是整套题提交和整次评分，不是逐题推进/逐题修改/逐条反馈的教学节奏。还缺本轮混合题型与题目语言。无需为了视觉对齐重写已验证权限和幂等门，但前端应把题目卡、作答动作、建议反馈与后续修改连在一起。

目标代码中“未作答直接看答案”会进入revealedOnly且锁输入；已graded返回也可能直接带key。我们的显式reveal门更严格，应保留，不需要降低隔离去追求逐字复刻。题目flag问题反馈是另一个明确入口，当前没有同等逐题入口。

## 6. 批注是阅读上下文中的小动作，笔记本是随身回看

`HJe` [2420171,2421347) 不是只发一句note：先按region切分选区，再提交exact/prefix/suffix/position_hint/section_heading及颜色；先临时绘制，成功再绑定服务ID。`OJe` [2416217,2416572) 区分lesson、conversation消息序号/时间、exercise set/qid/block/attempt；`Fie`列出stem、choice_explanation、solution、reference_answer、feedback。`PJe/IJe`配合DOM区域重绘/跨段定位。

`Tit`将全教材重点按KP→section/source分组，`Fit/Uit`呈现悬浮便携笔记本、颜色筛选、当前知识点标记和回原文动作。这个机制让记笔记不用离开刚读的段落。

本地四类批注、固定版本、旧反馈stale和跳回门已实现且更严格绑定持久ID，应保留。当前整页笔记列表/大表单仍打断阅读，可把高亮色、添注、改色和小笔记浮层放近选区，便携本在侧面轻展开；不能因此放松已揭示答案门、旧版本定位检查或复制原站的消息index弱身份。

## 7. “个性化总结”实际是章节素材→可读产物

`Ght` [2935554,2939102) 先展示本章learned_kp/total_kp、qa_rounds、highlight_count、note_count，明确这些是学霸笔记素材；卡片的 `Uht` [2929866,2934140) 针对具体artifact_type生成。未准备章节禁用；素材不足3个已学点时出现低素材确认，再选择语言和本次确认。阈值是客户端提醒，不是已验证的教学有效门槛。

`SIe → l3e → ld`进入独立run。四阶段是 `read_materials → write_note → validate_repair → package_offline`；阶段说明写明按概念域重组全章、渲染诊断与定点修复、打包离线。只能证明客户端识别并展示这些阶段，服务端是否执行这些动作需要运行证据。

`gft` [2953415,2954970) 为章节产物开独立reader；`pft/fft`把latest artifact和历史run分开，仅success且has_content的run可读/下载。`Xht`以HTML `srcDoc` sandbox iframe呈现纸面内容，顶栏是返回章、run版本与下载；深色模式仅壳层，笔记始终浅纸。`koe`按artifact或固定run取blob，撤销object URL并处理下载状态。

当前总结已有真实来源+个人记录输入、范围截断说明、指纹新鲜度与Markdown/离线HTML，不能降格成模板。差距在于它仍是“任意选章表单+Markdown输出”的同一个大dialog，缺少本章个人素材可见性、专门成果阅读状态及历史run阅读体验。先把章节总结从全书工具中释放出来，再谈纸张、字号和收藏封面。

## 8. 课题研究的区别在“研究意图—工具动作—返回证据”

`Lut` [2824937,2829317) 是富输入：@材料、拖入材料chips、粘贴/拖图；上传未完成不能发送，content可为字符串或结构化数组。关联知识库与联网搜索是互斥的本轮开关，分别强制 `search_kp_hybrid` 或 `web_research`；会话/发送开始后复位，未选教材时提示去右侧勾选。

`xh` [902590,908869) 带content/client_message_id/force_tools发流；message.delta/done、item.added、tool_step、moderation、aborted、title更新分别改变状态。tool_step按tool_call_id聚合，function_call_output到达后清该call临时步骤，历史卡读取持久process_steps。只有最终Markdown消息不足以表达这一条链。

`Vct/Hct/wct`按typed item展示调用与结果；材料读取显示文件名/页或行范围、被删材料状态；KP搜索显示total_unique、searched_textbook_count、partial/失败范围；精读知识点显示has_lesson/has_conversation等；read_textbook绑定实际page_start/page_end/pages。所谓“精读知识点”在这里是工具卡结果，**不是由工具名推导出的独立精读页面**。

`ioe` [2784425,2787283) 的research卡把过程、`sources_for_citation`和完整搜索报告分别折叠；`_ct` [2787726,2788375)将每来源的URL、标题/站点等做真实链接。未知工具仍可展开参数与原始output，不能悄悄丢掉与回答相关的工具证据。

当前本地课题有私有材料、关联教材、后文关键词检索/页码和最终引用，属于可用基础；仍没有富材料引用、inline视觉模型、force-tools、工具timeline或联网研究。下一UI可以预留正确组件，但没有后端真实工具事件时只显示真实本地检索范围/进度，不造“已联网”卡和搜索步骤。

## 9. 一个必须纠正的旧结论：全书QA路由已迁移

生产路由 `/textbook/:textbookId/qa → Zit`确实存在；完整Zit只展示“答疑功能已迁移到课题工作坊”，按钮去/workshops。它不是现行全书聊天实现。本地“关联教材→课题问答”符合这个迁移方向，不应为追求路由表齐全再造旧页。原报告若只依据路径把它算作可用功能，应降为迁移入口。

## 10. 有证据的下一UI顺序

1. 保留本地身份、来源、任务和答案门，重做阅读壳层：细森林绿导航、独立章节列、中央最大约800px正文；右助教可收起。章节/知识点/总结成为有状态的面，不再不断打开大dialog。
2. 主操作随状态变化：先准备章节、再开始学习、阅读时只留紧凑讲义/练习和必要操作；设置/管理/导出进更多菜单，减少读前工具墙。
3. 先修容器身份、焦点、选区和滚动，再加150–300ms轻motion。返回KP恢复位置、笔记深链优先、用户上滚不被强拉底部；尊重prefers-reduced-motion。这是实现选择，需本机浏览器验证。
4. 逐题学习卡、贴选区批注、章素材摘要、全屏成果reader分别做纵切；整套已有服务可先保留，通过清楚的状态交互提升体验，不伪称后端已有逐token流或研究工具。
5. 全部可见能力带证据状态：已有本机功能、目标静态支持待runtime、未来未实现各自列明。纸面风格与真实教材任务结合，不用大假书封、无依据语义图或假过程动画制造“高级感”。

本轮新源集128声明/138257字节已单独冻结供root运行真正REA；未重跑旧full bundle内存失败，也未把旧96声明的semantic unknown包装成全量恢复。后续新REA Evidence ID与root运行视觉证据应补入总报告，本worker不代签独立验收。

# R01：上传、资料库、OCR/目录、章节流水线与知识结构

状态：静态调查已冻结，2026-11-16。**以下 observed-static 指公开客户端代码中的实际语法、参数、字段消费与条件分支；不是已经操作目标服务。** 服务器算法、计费与运行结果须由 root 的浏览器/网络证据另证。未执行 bundle，未读取任何教材、账户数据、运行目录或密钥。

## 1. 结论与这次补上的遗漏

1. PDF 上传前先做配额检查与“分章节/全书”解析方式同意；两模式有独立报价和余额不足状态。上传完成不等于课程完成。
2. 上传有 OSS 凭证、分片进度/断点、续签、complete 确认及受限 legacy 回退，不是一个普通 multipart 按钮。进度条部分来自时间估算，不能据此宣称服务端实时处理百分比。
3. OCR、目录识别、整书提取、所选章节批量提取、单章 extract→prep 是分开的状态/恢复链。把它们合并成“解析PDF→分章”会漏掉核心产品行为。
4. 单章解析可离页后台接续，取消在提取阶段与准备阶段有不同语义；有单独取消请求，关闭流只是停止客户端追踪。
5. 知识结构数据不止 book→chapter→KP 包含关系：客户端消费前置知识、难度、知识点间边、教材页段、双语名称和教学推荐顺序。主消费界面是章节卡/难度条/列表；**本调查没有看到可据以确认自由拖拽节点连线图的渲染链**。
6. 章节准备与“个性化总结”是两类产物；前者整理知识点/准备讲解，后者走章节 artifacts 独立任务和阅读页。总结的细分产物、历史/下载由 R02 报告承接，不能用本项目的通用个人总结弹窗代替原站语义。
7. 课题持久材料、教材、会话临时图片是三套对象。`qAe/GAe` 的 OSS 是 conversation inline-images，不能错算作 workshop 材料上传。

## 3. 上传与教材书架

### R01-U1：用户选择文件→同意解析模式→上传→处理页

**调用链**：`/upload` 的 `yZe` → `pYe` 选择/拖入 → `kre` 格式/体积校验 → `xZe` 本机 PDF 页数估计 → `iJ/NOe` 报价 → `Sre` 显式同意 → `PYe.startUpload(file, mode)` → `IYe/DYe` 或 `ao.upload` → `/textbook/:id/extraction`。

- `yZe` 在上传前读 `f0()` 的教材数量配额，非 tester 且 `textbook_count >= textbook_limit` 时显示“教材数量已达上限”。这是客户端条件，服务器真实额度值未知。
- `pYe` 接收 PDF MIME 或 `.pdf` 后缀；默认文案最大300MB/3000页，`kre` 实际体积常量 `300*1024*1024`。`pYe` 的 `maxPages=3000` 是呈现参数，未在该组件中实施页数拒绝；`xZe` 得到 `numPages` 是给 full quote 估算。**服务器3000页限制的实际执行不由静态文案证明**。
- `Sre` 默认选择 chapter。chapter 描述“识别目录、整理章节，想学哪一章再单独准备该章的知识点，按需付费”；full 描述“目录识别完成后自动解析全部章节，第一章完成即可开始学习”。TOC quote 与 full quote 各有 loading/error/retry/sufficient/shortfall，full 可因页数检测失败等原因 unavailable；不能用默认价格代替报价结果。
- `Sre` 取消上传前同意只关闭弹窗，不创建教材。它明确“删除教材不会退还已消耗的积分”。费用是否当期为0须查真实 quote；同 bundle 公告有“章节备课不再扣积分”文本，不能将“按需付费”扩展为 prep 必然收费。

**定位**：`yZe` B[2371126,2373914)、`pYe` B[1929942,1933505)、`kre` B[1940675,1941041)、`xZe` B[2370561,2371058)、`Sre` B[1935716,1940261)、`PYe` B[1945090,1947788)。

### R01-U2：直传协议、进度、取消与失败

`PYe` 为一次上传生成 `client_upload_id`，随 `filename/size_bytes/extraction_mode` 提交。`OX()` 根据本地开关和默认常量选择直传或 legacy；本轮不读取用户本地开关，故实际选择未知。

直传 `IYe` → `Are` (`POST /textbooks/upload-credentials`) → `TYe` → OSS SDK `IX` / `zAe` 分片上传，使用返回 `bucket/region/endpoint/object_key/part_size/credentials`；进度回调保存 checkpoint。`AYe` 续签绑定原 textbook_id；失效续签只容许一次后明确 `UPLOAD_SESSION_NOT_FOUND`。`OYe` 调 `POST /textbooks/:id/complete`：区分网络错误、`UPLOAD_COMPLETING` 等，受代码中的次数/间隔上限约束。异常分类 `tf` 可触发 `DYe` 回退 `ao.upload`；不是所有业务错误都重传。legacy 为 `POST /textbooks?client_upload_id=…&extraction_mode=…` multipart，10分钟请求超时。

`EYe` 订阅 `upload-events`，仅记录此公开构造逻辑，不取得任何 token。`PYe` 消费 `milestone`、`oss_done/complete`、`error`。`uploading` 的用户百分比是传输百分比×0.6；`processing` 按秒增加并结合 milestone，限制95/99，完成响应还会将 milestone 设为总数。因此这是**混合估算显示**，不是真实 OCR 页级百分比。成功响应+ready 后1秒转 extraction 页。

`IYe` 的 abort 在新一轮/组件卸载时取消 SDK 并以递增 generation 避免旧结果落入新状态。当前 `pYe` 上传中 UI 没有显式“取消上传”按钮证据；不能把 hook 的 abort 当用户可点功能。失败显示教材满/每日上传次数/加密PDF等区别，清理本地进度；服务器是否自动清理半上传教材未知。

**定位**：`ao` B[891180,892524)、`IYe` B[1943844,1944486)、`TYe` B[1942558,1943312)、`OYe` B[1943372,1943844)、`DYe` B[1944497,1944834)、`EYe` B[1941041,1941539)、`OX` B[894836,894934)。

### R01-L1：书架不是平面列表

`E$` → `bf` 教材+`_Oe` 文件夹 → `tKe` 书架。`ZGe/JGe` 处理拖拽、跨容器移动、创建文件夹、打开/重命名/删除等；`Ck` 是 folder CRUD。`yOe` 将视图归一为 `{top_level:[{type:'folder'|'textbook',id}],folders:{folderId:[textbookId]}}`；`kOe` 同时更新教材的 folder_id/sort_order 和文件夹排序。

`TOe.submitLayout` 做 optimistic UI，保留旧教材/文件夹快照，连续拖动只排队最后一个快照，调用 `PUT /textbooks/layout`；失败恢复旧视图；`LAYOUT_SNAPSHOT_STALE` 刷新并提示“书架已在别处变动…重新拖动”，invalid 提示刷新，网络错误提示已恢复。`E$` 删除教材成功会失效列表/配额并清理 teaching/artifact/chapterflow/练习等本地 store，重命名经 `TJ` 弹窗与 `ao.renameTextbook({new_name})`。服务端 folder 删除后教材归宿、最大层级和冲突版本算法仍未知。

## 4. OCR→目录→章节的三个处理层

### R01-P1：extraction 页和 OCR 衔接

`Pat` 是独立处理页。`MOe` 读取 `Ml.getExtractionStatus`；`Cat` 将 `agent_status=extracting/ready/unavailable/failed` 映射 extracting/completed/unavailable/failed，其他情况按 `toc_requested` 分 OCR 或 pending。上传跳入时 `fromUpload=true` 会触发目录请求；从既有教材进入 pending 则重新显示同意/报价。不同来源入口不能当相同自动行为。

`mJ` 轮询 `GET /textbooks/:id/ocr`（5秒），404 不重试并由页面回首页；读 `status/done_pages/total_pages/retryable/health`。`YZe` 将 completed **或 partial** 都视为 OCR done；partial 不意味着每页都有文字。`Mat` 在 OCR 完成后失效 extraction 状态，并在取得更新的 pending 响应后触发 TOC，防止使用旧状态重复启动。`xJ.retry` 单飞调用 `/ocr/retry`；409/OCR_RETRY_NOT_ALLOWED 刷新而不再造失败，503/OCR_RETRY_UNAVAILABLE 显示可重试提示。

本范围内未见独立 `/ocr/cancel` 请求或用户可选页范围控制，不能声称原站支持这两项。当前副本的≤5页 OCR 是本机适配，非该 bundle 证明的原站分批策略。

**定位**：`Pat` B[2728802,2734240)、`Cat` B[2725879,2726103)、`mJ` B[1145869,1146245)、`xJ` B[1146340,1146971)、`YZe` B[2393931,2394322)、`Mat` B[2728341,2728802)。

### R01-P2：TOC 处理流与整书模式

`Pat.te` → `Ml.triggerTocExtraction` (`POST /textbooks/:id/agent/toc`)；full确认 → `Ml.triggerExtraction` (`POST /textbooks/:id/agent/knowledge-graph`，可选force)。`bat` 在 extracting 时 GET knowledge-graph/stream：只收 `chapter_id==='toc'` 或未给 chapter_id 的 `process_step`；`gat/mat` 将思考/文本拼接、将同一连续 tool_call 的 executing→完成合并，供“最新工具活动”展示。`complete.total_chapters` 完成；`NO_TEXT_LAYER/CORRUPT_PDF` 变 unavailable，其他 error.message 变 failed。

网络流失败时 `bat` 改3秒状态轮询，ready 后再GET knowledgeGraph统计 chapter_titles，failed/unavailable分别展示；15秒 extraction status 刷新是另一层防僵死。组件离页会 abort stream/清轮询，但未见对TOC的服务端 cancel。因此不可将“离页中断流”报告为“后台任务已取消”。

完成页可“开始学习”；full 模式读取 active_batch 并提示剩余章节仍后台处理中，首章可先学。产出首先是可进入的章节目录及处理状态，不保证所有知识点/讲解已齐。

**定位**：`Ml` B[1120731,1121504)、`bat` B[2718048,2720908)、`gat` B[2717082,2717315)、`mat` B[2717315,2718034)、`Pat` 同上。

### R01-P3：批量选章提取

`JDe` → `ob` (`chapters/extraction-status`) → `LIe` 分 pending/extracted/no_content/busy；仅 pending 可选。`GDe` 维护选中集；`jIe/EIe` 按章号去重排序，用逗号传 quote（UI有300ms防抖），返回余额/total/shortfall/sufficient；`KDe` 显式确认 → `AIe POST chapters/batch-extract {chapters}`，接收 batch_id/accepted。

`gJ/TIe` 每3秒 GET batch，404/终态停止；章节状态推进会失效 knowledgeGraph，终态失效 extraction-status。`uMe` 经过确认 POST batch/:id/cancel；返回状态写入缓存并按实际产物变化刷新知识结构。UI消费 queued/dispatched/failed/skipped_credits/no_content 等，故部分章节跳过积分不足与“全部成功”不是同一种结果。已完成部分在取消后是否保留的后端细节需运行证据，不能仅由缓存 invalidation 推断。

**定位**：`JDe` B[1178861,1180216)、`KDe` B[1176107,1177084)、`LIe` B[1150839,1151101)、`EIe` B[1144080,1144377)、`AIe` B[1144377,1144525)、`TIe` B[1144525,1144662)、`gJ` B[1145326,1145855)、`uMe` B[1185074,1185536)、`_Ie` B[1144662,1144795)。

## 5. 单章 flow / quote / prep：完整流程

### R01-F1：入口与报价

知识结构空章节卡 `cJe/oJe` 的 onPrepare 导航 `/textbook/:id?prep=<chapterNum>`；`Yit` 选择 `zie` 解析面板（知识点 reader 主线由 R02 追）。`zie` 首先 `Q5e GET flow`，若 pending/running 则 attach；空章/no_content直接显示“本章无知识点”。`AZe` 综合服务器历史、本地活动 flow、OCR错误和是否 extracted 产生面板状态。

`_Ze/Oie` 决定需要报价的 stages：未提取 `['extract','prep']`，已提取或prep取消 `['prep']`。`wIe/Z5e GET flow/quote?stages=…`；报价字段被消费为 total_credits/extract_credits/prep_credits/prep_estimated/sufficient。点击“开始解析” `X5e POST flow {stages}`；onSuccess 用 flow_id 重新 attach。OCR 未就绪显示等待/重试，TOC_NOT_READY、NO_KPS、CONFLICT、LIMIT、ALREADY_PREPARED、QUEUE_UNAVAILABLE、TIMEOUT、额度/每日限额等分别处理。没有静态固定价格证明。

### R01-F2：事件和状态，不是进度动画替代任务

`Jh` 是按 textbookId+chapterNum 索引的运行 store。`attach` 首次读 `e3e` 流，刷新后可用 flow_id/startedAt 重新接；`snapshot` 给完整 flow/stages/entries_by_stage，`stage` 更新阶段，`entry` 更新该stage条目，`run` 保存状态/failure_reason/error_code并失效教材知识结构/章计划/章提取状态。stage/entry/run会拒绝不匹配flow_id。按秒计算 elapsed/idle；45秒无事件触发重连，最多5次，1/2/4/8/16秒退避；活动流断连进入 stalled，不能继续附着时 detached；最终 finished/failed 停driver。401/403等 fatal分类不靠无限重试掩盖。

`KZe/GZe` 展示两步“整理知识点 / 准备讲解”，展开可见阶段条目、耗时、空闲提示，收起不取消。文案明确“可以离开这个页面，两步会在后台自动接续”。`J5e POST flow/cancel` 才是服务端取消请求。取消确认文案：extract阶段“任务会立即停止，已产生的半成品会被清理”；prep阶段“之后可以随时继续”。这是**客户端告知的语义**，实际服务器清理需实证。

`gV/HZe` 将 completed(+含prep)显示done，extract-only完成回idle但extracted=true；extract失败重跑extract+prep，prep失败/取消只重跑prep。完成文案“知识点和讲义都已生成，从左侧选择知识点即可开始学习”。用户最终可消费的是知识点列表/教学顺序/讲解材料，不是单纯任务成功toast。

**定位**：`cJe` B[2408142,2409191)、`zie` B[2396204,2398933)、`AZe` B[2376762,2377814)、`Oie/_Ze` B[2377990,2378146)、`Z5e` B[847353,847601)、`X5e` B[847016,847223)、`Jh` B[857035,861099)、`J5e` B[847601,847720)、`GZe` B[2390619,2392995)、`HZe` B[2387064,2387793)、`gV` B[2376163,2376520)、`WZe` B[2387793,2389029)。

## 7. 课题材料与临时图片

### R01-W1：创建/追加材料、预览、管理、OCR

`eIe` 先 `UOe POST /workshops {name,description}`，再按顺序 `aJ POST /workshops/:id/files` 逐个multipart；每个请求可AbortSignal，timeout600s。任一步失败/cleanup尝试删刚创建的课题，避免留创建半成品；删除结果被catch吞掉，不能保证服务器真的清理成功。已有课题追加是 `$dt→XOe→aJ`，成功后invalidate当前workshop。

材料选择支持 PDF/JPG/JPEG/PNG/Markdown；PDF文案≤100页、md≤5MB。单文件MB存在**客户端文案不一致**：`Ldt` 静态写100MB，`Xdt/$dt` 读取`workshop_material_max_mb`、fallback30。不能仅引用其中任一数字断言服务器现行额度。`$dt`还存在文件名含`over100`的拒绝分支（疑似演示/遗留逻辑），不是可靠的真实页数检测；其阶段进度由定时器推进，成功响应才100。运行时应核真实文件与错误，勿将动画当真实解析测量。

`GOe PATCH files/:fid {new_base_name}`；`qOe DELETE`；`KOe GET preview-url`。`tdt` 按file_type分 PDF(Qut分页缩放)、image(img)、md(fetch预览URL→安全reader)，文件切换重置页码/内容；网络失败可见，MD可重试。

`nIe→YOe POST files/:fid/ocr`：先把缓存该文件 `agent_status` 标为ocr_running，失败回滚previous、结束invalidate；Jut含OCR_RUNNING/OCR_NOT_APPLICABLE/PAGE_COUNT_EXCEEDED/NOT_FOUND错误文案。此处没有凭据直传链，也未确认OCR后台引擎。

**定位**：`eIe` B[1136187,1137014)、`aJ` B[1134362,1134570)、`XOe` B[1135469,1135643)、`GOe` B[1134679,1134828)、`qOe` B[1134570,1134679)、`KOe` B[1134828,1134967)、`YOe` B[1134967,1135102)、`nIe` B[1137214,1137700)、`tdt` B[2845569,2848980)、`$dt` B[2881907,2884199)、`Ldt` B[2879558,2880961)、`Xdt` B[2893087,2894586)。这些小API按原bundle字节复查，不能由调用者片段推定所有依赖已覆盖。

### R01-W2：会话临时图片不是上面的持久材料

`Mut→GAe→qAe`；`PX(conversationId)` 解析为 `/conversations/:id/inline-images`，credentials → OSS put → `/:inlineImageId/complete`。UI状态Map保存pendingId/AbortController；单次图片≤10MB、格式png/jpeg/webp/gif、图片数由LH限制；成功变inline_image_id等chips，取消/切会话/卸载abort，失败移除pending并反馈。它可为模型视觉追问提供输入，但是否实际调用视觉模型、供应商处理过程由R02运行链/网络另证。

**定位**：`PX` B[897350,897460)、`qAe` B[898393,898927)、`GAe` B[899038,899228)、`Mut` B[2820881,2822607)。

## 9. 未知与给 root / critic 的具体复核问题

- **runtime未知**：两模式当前是否都可用、真实报价/当前会员门、重复上传/超限服务器如何处理、full模式首章就绪的实际时刻。此处只证明客户端有分支。
- **OCR未知**：服务端供应商、识别语言/页级partial策略、排队/取消/费用。客户端把partial视为流程可接续，不是质量保证。
- **TOC未知**：自动目录使用书签/可见目录/模型/工具的具体决策、实际工具参数与章节边界质量。`process_step`能展示工具执行，不证明每工具都在当前运行被调用。
- **KG未知**：边提取/先修推理算法、graph版本/来源校验、跨章边方向与语义、是否另有懒加载图画布。已选声明/主路由未提供自由节点可视化证据，不能全站断言不存在。
- **任务未知**：SSE停止不代表后台取消；服务器锁/幂等/持久性、取消清理、刷新attach的真实响应要用网络验证，客户端防旧flow不能替代服务端安全。
- **材料未知**：100MB文案与配置fallback30冲突、`over100`文件名分支的实际影响；请用真实自编超100页文件核对，不用文件名模拟通过当页数检测。
- **复核边界**：查hash与span是否能复得同一原文；确认声明边界与原始hash；逐个P0补UI动作/实际响应/产出截图，结果仍按tested/static-only/blocked归类。原EVI-X、当前产品生产代码均未修改。

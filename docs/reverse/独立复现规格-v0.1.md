# Mentrix 能力的独立复现规格 v0.1

状态：proposed。依据：主交付 JS、REA 业务片段、API 静态分析、登录后只读界面和当前公开配置。此文件是可实施的设计规格，不是 Mentrix 原始工程，也不表示已经实现下述组件。

原 EVI-X 工程保持不动。若在后续参赛副本使用这些思路，应创建完全独立的工作目录、环境、数据库、存储前缀、域名/端口和凭据；不能把对方账号会话或原站 API 当成复现版后端。

## 1. 两层组织：阅读学习与材料研究

复现时把两个容器分开：Textbook 用于结构化教材、章节、知识点；Workshop 用于短篇材料、文件和研究对话。用户偏好、额度、批注、朗读为共享能力。

建议组件边界：

```text
web/
  app-shell/             导航、主题、认证边界
  auth/                  密码/短信入口、刷新与退出
  textbooks/             列表、上传、目录/提取状态
  chapter-learning/      目录、知识点、讲解和追问
  exercises/             练习配置、作答、解析、草稿
  artifacts/             章节笔记、过程、导出
  workshops/             课题、文件、对话
  reader/                PDF、Markdown、公式、引用
  annotations/           划线、笔记、重定位
  tts/                   切块、播放、取消与预取
  account/               偏好、配额、会员展示
  infrastructure/        API、SSE、上传、查询缓存
api/
  authentication/        账户与会话
  materials/             文件、上传确认、文档元数据
  processing/            OCR、目录、章节任务与状态
  learning/              讲解、练习、产物、学习记录
  conversations/         材料范围、会话、消息流
  annotations/           用户批注与锚点
  quota/                 测试额度、并发任务与成本记录
```

这里没有指定数据库或模型服务商。可以沿用后续独立副本已有的 Next/FastAPI/PostgreSQL 基础，只迁移业务组件和协议；不必为了外观一致把整个技术栈重写为目标的 Vite 应用。

## 2. 数据模型：自行设计而非恢复 DDL

| 实体 | 建议职责与关系 | 必须独立决定 |
|---|---|---|
| User/Preference | 账户、语言/讲解偏好、主题 | 登录方案、会话安全、个人信息范围 |
| Textbook | 所属用户、文件引用、状态、目录版本 | 删除策略、共享权限、版本定义 |
| Chapter/KnowledgePoint | 教材内章节与知识点，关联来源范围 | 排序与稳定ID、引用粒度 |
| ProcessingJob | 上传后处理、章节 flow、进度、取消 | 幂等键、并发限制、恢复策略 |
| Lesson/Message | 讲解版本、对话消息、来源引用 | 模型记录、提示词版本、存储与审核 |
| ExerciseSet/Attempt | 题目、作答、解析、反馈 | 评分规则、答案权限、提交幂等 |
| Artifact/ExportJob | 章节产物、格式、下载与版本 | 模板、文件正确性、过期策略 |
| Highlight | exact/prefix/suffix/occurrence 与来源ID | 重定位失败策略、版本绑定 |
| Workshop/Material | 课题与多文件，关联会话及教材范围 | 处理限制、文件可见性 |
| QuotaLedger | 预估、预留、结算/释放及任务关联 | 单位、可撤销边界、账本一致性 |

若为了最小演示省去会员付费，也必须保留生成任务的并发、取消和失败状态；不应把所有任务都实现成一个无持久化的“正在加载”布尔值。

## 3. 接口与状态契约

浏览器侧保留统一适配层，隔离 JSON、text、blob、SSE 和直传五类响应。不要用一个 `response.json()` 处理所有类型，也不要把 HTTP 200 直接等同业务成功。

| 能力 | 建议兼容的边界 | 状态/失败必须可表示 |
|---|---|---|
| 认证 | login/refresh/logout、用户偏好 | 未登录、过期、单次刷新重放、退出清缓存 |
| 上传 | validate→credentials→transfer→complete | 不支持/过大/损坏/加密、会话失效、上传与确认失败 |
| 文档处理 | OCR/TOC/章节任务 | queued/running/ready/failed/cancel-requested；这里的枚举为复现设计，非原服务端完整枚举 |
| 讲解 | 获取现有文本、开始任务、过程流、追问 | 未就绪202/204、增量、结束、错误、连接断开 |
| 练习 | quote→generate→set→attempt→reveal | 取消、恢复、草稿、解析前后可见性 |
| 章节产物 | generate→progress→content→download | 分阶段失败、重试与版本、坏包拦截 |
| 课题 | 课题/文件/会话分层 | 空课题、材料未就绪、文件移除后的引用 |
| 批注 | 文本锚点+来源版本 | 多处命中、来源改变、重定位失败 |
| 朗读 | 切块、预取、暂停/继续、stop | 总长/单块限额、超时、切页与重播 |

原客户端存在的 SSE 事件包含 queued、text_delta、process_step、moderation_regenerating、done、error 等；复现后端可以实现一个明确的子集，但前端应对未知事件容错，并以最终任务状态判断结束，不能只靠连接关闭。

## 4. 核心交互与版本规则

1. 教材上传前给出真实限制；配置值、错误提示和说明文案使用同一来源。当前目标存在课题文件 30 MiB 配置与 100 MB 文案分歧，复现时应修正这种不一致。
2. 文档处理完成后再允许知识点学习。目录和知识点应有来源、版本与稳定身份，刷新不能重新造一套无法关联批注的ID。
3. 讲解风格先保存成功，再启动“按该风格重新生成”；保存失败不能暗中生成。
4. 练习草稿独立于已提交 attempt，刷新恢复后仍须明确提交，不用本地草稿代替服务器提交成功。
5. 批注保存时绑定来源版本，exact/prefix/suffix 加 occurrence 只是一种定位手段；找不到时显示失效，不错误跳到相似段落。
6. TTS pause 与 stop 区分：前者保留当前音频位置；后者取消请求、清队列。跨刷新恢复要另做功能，不能误称原代码已有。
7. 文本、引用和生成版本分别保存。新生成不能静默覆盖用户自己的笔记与答卷。

## 5. 复现验收用例

以下是后续实现必须执行的测试计划，本轮未执行：

| 编号 | 测试 | 可核验通过标准 |
|---|---|---|
| R01 | 并发请求同时收到401 | 只发起一次刷新；原请求各至多重放一次；刷新失败统一退出 |
| R02 | 文件限制边界 | 配置、页面说明、校验与服务端拒绝一致；MB/MiB口径明确 |
| R03 | 上传中断后重试 | 已有会话有明确恢复/失效策略，不重复确认或重复建教材 |
| R04 | 章节任务取消 | 展示cancel-requested及最终状态；不把已提交取消当任务已停 |
| R05 | 流式讲解断开 | 保留已接收内容并显示未完成；不会写成成功完成版本 |
| R06 | 偏好保存失败 | 不启动重新生成，提示可重试且不消耗一次生成 |
| R07 | 练习草稿与提交 | 刷新不丢草稿；重复提交受幂等控制；答案权限一致 |
| R08 | 批注同文重复与改版 | occurrence区分命中，来源改版不静默跳错位置 |
| R09 | TTS暂停/停止/超时 | pause可同实例恢复；stop终止预取；失败不无限重试 |
| R10 | 导出产物 | 实际打开文件、检查内容/公式/分页；不以下载HTTP200代替验收 |
| R11 | 配额与并发 | 预估、预留、失败释放和完成结算可追溯；无重复扣除 |
| R12 | 权限 | 不能凭ID读取其他用户教材、文件、批注、会话或下载 |

## 6. 后续参赛副本的收敛建议

这部分属于建议，不是目标产品事实：原 EVI-X 已有模型配置、结构化提案、版本、报告编辑和证据链能力。参赛副本可把“教材/材料→章节知识点→讲解→练习反馈”的一条基础教育课堂任务做完整，保留来源引用和教师确认，将现有报告编辑器用于教案/学案。会员、邀请、支付等模块通常无需跟随复现。

在原工程外复制一个可审查的源码快照，并分别初始化数据库、凭据与存储；用户原有未提交变更应进入副本快照，不能只复制 Git HEAD 而漏掉当前工作状态。此处是后续执行规格，本轮没有执行整仓复制或参赛应用改造。

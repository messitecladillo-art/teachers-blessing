## 优先纵切：完成一课时任务

拟先用一个具体教学任务验证价值，例如“向初中生讲清同分母分数相加，并检查学生是否理解等分”。其输入包含学段、学科、课时、教学目标、所选教材页和明确标注的班情材料；不是让用户反复填写已经提供过的项目背景。

1. **任务卡**：固定这次要完成什么、先备知识和可审阅成果；目标变化保留版本。
2. **任务驱动导师**：每次安排一个小挑战，让学习者解释、演示或设计；回答与误解修正关联具体证据。仅浏览内容、自标掌握或AI建议分不自动形成能力认证。
3. **教学成果工坊**：形成教案、学生任务单、图示、形成性评价和教师版参考/来源附录。每步可修订、单独再生成，变更来源后原确认失效。
4. **图练习**：学习者补图、改边并解释依据；可确定计算的部分用规则核对，开放解释保留AI建议与教师审阅，参考图/量规有明确揭示动作。
5. **试讲与复盘**：用户主动提供合成或已授权去标识反馈后，整理困难、反例和下次调整；不从个人账户记录自动拼成班级数据或宣称干预有效。

这五步是产品适配提案，尚未实现为完整界面。当前可复用的基础是教材/知识点、课题关联、作答/批注、个人总结、版本指纹、原门户的教案/PPT入口及课堂CSV证据工具。它们仍需贯通，不能将“已有入口”写成“完整工作流已上线”。

## 核读后新增的关键方法

- Matt的[teach](../skills/vendor/mattpocock/teach/SKILL.md)及[理解记录](../skills/vendor/mattpocock/teach/LEARNING-RECORD-FORMAT.md)区分目标、接触过的材料、已展示理解和误解纠正。我们借其设计产品；不在当前开发聊天中自动启动`/teach`、给用户建学习档案或要求重新访谈。
- Anthropic的[研究综合](../skills/vendor/anthropics/product-management/skills/synthesize-research/SKILL.md)可指导教研复盘；[数据验证](../skills/vendor/anthropics/data/skills/validate-data/SKILL.md)要求保留样本、分母、缺失和解释边界。这些属于教育场景推导，不是上游现成教育插件。
- 图示内容正确与图面清晰分开验收。Diagram Design并非现成拖拽编辑器；当前只选入部分参考，图示结构、编辑表单和题目协议需要自己实现。当前知识图鉴也不代表已接入语义图谱、GraphRAG或通用图判题。
- CAD继续保持预留。真正接入时再核查运行环境、依赖许可、参数/单位、模型与导出一致性；上游仿真不冒充课堂实测。没有因为本次核读而运行安装器、CAD服务或遥测。

## 每项新能力的验收约定

| 检查轴 | 必须回答 |
| --- | --- |
| 任务与成果 | 师范生/教师具体完成什么，得到什么可修订成果，是否解决真实教学任务 |
| 来源与内容 | 每项关键教学主张能否核对原文与版本，片段不足/分歧如何呈现 |
| 学习证据 | 保存的是本人自述、具体作答、AI建议还是教师确认，能否回到原证据 |
| 审阅与变更 | 谁确认了什么，材料/目标更新后如何失效，学生版是否提前带答案 |
| 实际交付 | 文件能否实际打开、修改和打印，图与公式是否清楚，失败能否恢复 |

暂不增加无实现的产品卡片或宣称全库插件已启用。上游技能是方法来源，后续实现仍以本项目的来源、权限、预算和真实验收为准；不能以参考仓库名称代替产品差异化或教学效果证据。

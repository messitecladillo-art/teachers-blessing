# PDF 大文件与页数上限

按用户确认，本轮提高教材 PDF 的文件大小和页数上限：**300MiB（314572800字节）、3000页**。`learning/limits.mjs` 是服务端共享配置，上传入口、独立解析进程和公开配置均读取它；客户端从 `/api/v1/config/public.learningLimits` 获取限制，用于说明、文件检查和目录/OCR页码输入。

教材 PDF 与课题文件采用不同预算：课题文件仍为30MiB，Markdown为5MiB；图片像素、每课题文件数、1GiB私有存储、每次5页OCR及20页课程提案预算保持原值。上传采用原件流式写入，HTTP请求最长10分钟；JSON接口仍使用自身的短读取期限。取消、超限和解析异常不会伪装成ready。

解析子进程原先统一按课题30MiB检查原件，现按教材/课题类型选择正确限制。没有可靠目录的长PDF采用自适应页分组，最多100组，并标注“待修订”；页分组不是已证明的教材章节。已有目录、书签和人工校正流程继续使用其来源与修订。

文件上限与处理预算分别计算：提取文字仍最多400万字符、子进程最多180秒、IPC结果最多16MiB，并有原有内存/图片限制。超过这些预算会如实失败并提示分拆；不能据文件上限保证所有稠密或复杂300MiB文档均可完成。长教材进入问答后也继续采用有界片段检索，不会一次把3000页全部交给模型。

专项验证：

- 自编、无目录的真实3000页PDF完成提取，第3000页的已知文本可通过私有内容接口读回；目录分组不超过100且覆盖末页。本机这次约7.5秒，不能推广为所有文档的耗时。
- 一个带合法PDF对象与未引用数据流、实际超过31MiB的自编PDF完成上传，并真正经过独立进程提取；不仅检查上传返回值。
- 原有超页测试改为3001页，验证失败状态与PAGE_LIMIT；声明超过300MiB的上传在接收大正文前拒绝。没有构造或宣称已解析一个完整300MiB实体文件。
- OCR超过5页的请求仍会拒绝，容量调整没有扩大模型上下文或OCR任务预算。

公开运行入口：`node --test tests/study-pdf-capacity.test.mjs tests/study-learning.test.mjs`。测试使用自编合成材料、私有临时目录，没有真实学生资料，也不调用付费模型。独立审查另行执行了301页/3001页和请求边界检查。
